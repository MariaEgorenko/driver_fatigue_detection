## 1. Общее описание проекта

Система обнаружения усталости водителя представляет собой комплексное решение для анализа состояния водителя на основе компьютерного зрения и машинного обучения. Проект использует современные технологии для детекции лица, отслеживания положения головы, анализа глаз и рта с целью определения уровня усталости в реальном времени.

Основные функции системы включают анализ видеопотока в реальном времени, определение уровня усталости по нескольким параметрам, таким как PERCLOS (процент времени закрытых глаз), частота моргания, зевание, положение головы и отсутствие лица в кадре. Система способна обрабатывать как видеофайлы, так и прямые видеопотоки с камер.

Проект построен на базе FastAPI для REST API, SQLAlchemy для работы с базой данных, MediaPipe для детекции лица и OpenCV для обработки изображений. Архитектура follows принципам микросервисов с четким разделением на модуль машинного обучения и REST API сервер.

### 2.3 Поток данных

Поток данных в системе начинается с загрузки видео или изображения через REST API. Далее происходит обработка кадра в видеопайплайне, где детектируется лицо с помощью MediaPipe Face Mesh. Затем извлекаются признаки: Eye Aspect Ratio для глаз, Mouth Aspect Ratio для рта, положение головы. После этого вычисляются события: моргания, зевания, отсутствие лица. Далее PERCLOS и другие метрики рассчитываются в скользящем окне. Оценка уровня усталости определяется на основе совокупности всех факторов. Результаты сохраняются в базу данных и возвращаются клиенту через API.

## 3. Модуль машинного обучения

Модуль машинного обучения является ядром системы обнаружения усталости. Он расположен в директории ml/src/ и содержит все алгоритмы компьютерного зрения и машинного обучения, необходимые для анализа состояния водителя.

### 3.1 Детектор лица (FaceDetector)

Класс FaceDetector，位于 ml/src/features/face_detector.py, является основным компонентом для обнаружения лица в видеокадрах. Он использует MediaPipe Face Mesh для извлечения 468 ключевых точек лица.

Основные характеристики детектора включают поддержку как видеопотока, так и одиночных изображений, высокую точность благо��аря использованию предобученной модели MediaPipe, возможность настройки порогов уверенности детекции и трекинга.

Конструктор класса принимает следующие параметры: model_path — путь к файлу модели MediaPipe (по умолчанию face_landmarker.task), max_num_faces — максимальное количество лиц для обнаружения (по умолчанию 1), min_detection_confidence — минимальная уверенность детекции (по умолчанию 0.5), min_tracking_confidence — минимальная уверенность трекинга (по умолчанию 0.5), is_video_stream — режим работы видеопотока (по умолчанию True).

Метод detect выполняет обнаружение лица в кадре и возвращает объект FaceLandmarks или None, если лицо не обнаружено. Метод принимает frame — изображение в формате BGR (numpy array), timestamp — UNIX timestamp кадра. Возвращает FaceLandmarks с массивом точек формы (468, 3), нормализованных в диапазоне [0, 1].

### 3.2 Анализ глаз (EyeAnalyzer)

Класс EyeAnalyzer, расположенный в ml/src/features/eye_features.py, отвечает за анализ состояния глаз водителя. Основная задача — вычисление Eye Aspect Ratio (EAR) и обнаружение морганий.

Eye Aspect Ratio вычисляется по формуле Сукуповой и Чеха: EAR = (||p2-p6|| + ||p3-p5||) / (2 * ||p1-p4||), где p1 и p4 — внешние углы глаза, p2 и p3 — верхние точки, p5 и p6 — нижние точки. Среднее значение EAR вычисляется для обоих глаз и используется для определения состояния глаз.

Для правого глаза используются индексы точек [33, 160, 158, 133, 153, 144], для левого — [362, 385, 387, 263, 373, 380]. Эти индексы соответствуют нумерации точек MediaPipe Face Mesh.

Метод compute_ear вычисляет текущее значение EAR для переданных landmarks. Метод detect_blinks_and_closures обнаруживает моргания и длительные закрытия глаз с помощью конечного автомата с тремя состояниями: open (глаза открыты), closing (глаза начали закрываться), closed (глаза закрыты). Морганием считается переход из состояния closed в open при длительности в диапазоне от BLINK_MIN_DURATION_MS до BLINK_MAX_DURATION_MS.

Метод compute_perclos вычисляет PERCLOS — процент кадров в скользящем окне, где EAR ниже порога. PERCLOS является ключевым показателем для определения усталости водителя. Метод blink_rate вычисляет частоту морганий в морганиях в минуту.

### 3.3 Анализ рта (MouthAnalyzer)

Класс MouthAnalyzer, расположенный в ml/src/features/mouth_features.py, анализирует состояние рта водителя для обнаружения зевания. Основная метрика — Mouth Aspect Ratio (MAR).

Mouth Aspect Ratio вычисляется как MAR = ||top-bottom|| / ||left-right||, где точки определяются через индексы MediaPipe: top (13), bottom (14), left (78), right (308). При открытии рта ве��тикальное расстояние увеличивается, а горизонтальное остается примерно постоянным, что приводит к увеличению MAR.

Метод compute_mar вычисляет текущее значение MAR. Метод detect_yawn обнаруживает зевания с помощью конечного автомата с тремя состояниями: closed (рот закрыт), opening (рот начал открываться), yawning (зевание подтверждено). Для защиты от ложных срабатываний используется гистерезис с порогом 0.8 от основного порога MAR.

Зевание подтверждается, когда рот остается открытым более YAWN_MIN_DURATION_SEC (по умолчанию 1.5 секунды). Для сброса состояния необходимо, чтобы рот был закрыт минимум 0.3 секунды.

### 3.4 Оценка положения головы (HeadPoseEstimator)

Класс HeadPoseEstimator, расположенный в ml/src/features/head_pose.py, оценивает трехмерную ориентацию головы водителя. Используется метод SolvePnP (Perspective-n-Point) из OpenCV.

Метод estimate возвращает объект HeadPose с тремя углами: pitch — наклон вперед/назад (положительное значение означает наклон вниз), yaw — поворот влево/вправо, roll — крен.

Для оценки положения используется 3D модель лица с шестью ключевыми точками: кончик носа (индекс 1), подбородок (индекс 152), левый угол глаза (индекс 263), правый угол глаза (индекс 33), левый угол рта (индекс 287), правый угол рта (индекс 57).

Метод is_head_down определяет, опущена ли голова, на основе сравнения текущего pitch с базовым значением, определенным при калибровке. Во время первых 30 кадров происходит калибровка, и базовый pitch усредняется. Отклонение более threshold_deg считается как опускание головы.

### 3.5 Трекер присутствия (FacePresenceTracker)

Класс FacePresenceTracker, расположенный в ml/src/features/presence_tracker.py, отслеживает отсутствие лица водителя в кадре. Это важный индикатор безопасности, поскольку отсутствие лица может означать, что водитель отвлекся от дороги.

Метод update вызывается для каждого кадра и возвращает AbsenceEvent, если лицо отсутствует непрерывно более threshold_sec (по умолчанию 3.0 секунды). Событие генерируется только один раз за эпизод отсутствия, даже если отсутствие продолжается дольше.

### 3.6 Конвейер обработки видео (VideoPipeline)

Класс VideoPipeline, расположенный в ml/src/inference/video_pipeline.py, является основным интерфейсом для обработки видеопотока. Он координирует работу всех компонентов извлечения признаков.

Конструктор инициализирует все компоненты: FaceDetector, EyeAnalyzer, MouthAnalyzer, HeadPoseEstimator, FacePresenceTracker, FatigueScorer. Также инициализируется скользящее окно FeatureWindow для хранения исторических данных.

Метод process_frame обрабатывает один кадр и возвращает FrameResult. Для оптимизации производительности пропускаются кадры в соответствии с FRAME_PROCESSING_INTERVAL. Метод process_video является генератором для обработки видеофайла или захвата с камеры. reset_session сбрасывает состояние для новой сессии.

Метод _trim_window обрезает окно до MAX_WINDOW_SEC (60 секунд по умолчанию) для управления памятью. Все списки событий фильтруются по времени.

### 3.7 Оценщик усталости (FatigueScorer)

Класс FatigueScorer, расположенный в ml/src/inference/fatigue_scorer.py, вычисляет итоговую оценку усталости на основе всех признаков и событий.

Метод score принимает FeatureWindow и возвращает FatigueScore с уровнем усталости и всеми метриками.

Определение уровня усталости происходит по следующим критериям. Severe_fatigue (тяжелая усталость): PERCLOS > 0.70, или >= 4 зеванияний, или лицо отсутствует, или PERCLOS > 0.35 совместно с >= 2 зеванияниями, или PERCLOS > 0.35 совместно с head_down. Mild_fatigue (легкая усталость): PERCLOS > 0.35, или >= 2 зеванияния, или head_down. Alert (бодрствует): все остальные случаи.

Метод _calculate_confidence вычисляет уверенность оценки на основе количества выполненных критериев и размера окна. Для severe_fatigue возвращается 0.7 ��ли 1.0, для mild_fatigue — 0.6, для alert — 0.7 или 0.9 в зависимости от длительности окна.

### 3.8 Типы данных

Все типы данных определены в ml/src/types.py. Основные классы включают FaceLandmarks для хранения 468 точек лица, BlinkEvent для событий моргания, YawnEvent для событий зевания, AbsenceEvent для отсутствия лица, HeadPose для углов поворота головы, FeatureWindow для скользящего окна, FatigueEvent для событий усталости, FatigueScore для итоговой оценки, FrameResult для результата обработки кадра.

## 4. Backend API

Backend API построен на FastAPI и предоставляет REST интерфейс для взаимодействия с системой обнаружения усталости.

### 4.1 Точка входа (main.py)

Основной файл приложения位于 backend/app/main.py. Создает FastAPI приложение с настроенными CORS, middleware для метрик, роутерами для API.

Приложение включает следующие роутеры: /health — системное здоровье, /metrics — метрики Prometheus, /api/v1/analysis — анализ видео и кадров, /api/v1/events — получение событий.

### 4.2 Конфигурация

Конфигурация приложения определена в backend/app/core/config.py и использует Pydantic Settings. Параметры могут быть переопределены через переменные окружения или файл .env.

Конфигурационные параметры включают DATABASE_URL для подключения к базе данных, MAX_FRAME_SIZE_MB и VIDEO_MAX_SIZE_MB для ограничения размеров файлов, FRAME_PROCESSING_INTERVAL для пропуска кадров (каждый N-й кадр обрабатывается), FRAME_SAVE_INTERVAL для интервала сохранения результатов в БД.

ML гиперпараметры включают EAR_THRESHOLD (по умолчанию 0.20) для порога Eye Aspect Ratio, MAR_THRESHOLD (по умолчанию 0.50) для порога Mouth Aspect Ratio, YAWN_MIN_DURATION_SEC (по умолчанию 1.5) для минимальной длительности зевания, HEAD_PITCH_THRESHOLD_DEG (по умолчанию 20.0) для порога наклона головы, FACE_ABSENT_THRESHOLD_SEC (по умолчанию 3.0) для порога отсутствия лица, PERCLOS_WINDOW_SEC (по умолчанию 60.0) для окна PERCLOS, PERCLOS_MILD (по умолчанию 0.35) и PERCLOS_SEVERE (по умолчанию 0.70) для порогов PERCLOS, BLINK_MAX_DURATION_MS (по умолчанию 400) и BLINK_MIN_DURATION_MS (по умолчанию 50) для длительности моргания.

### 4.3 База данных

Настройка базы данных位于 backend/app/core/database.py. Используется SQLAlchemy с asyncpg драйвером для PostgreSQL.

Функция setup_db создает движок и sessionmaker. Функция init_models создает таблицы. Функция get_db предоставляет сессию через dependency injection.

### 4.4 Зависимости

Файл backend/app/core/dependencies.py содержит функции для dependency injection. Функция lifespan обрабатывает запуск и остановку приложения, инициализируя ML пайплайн и базу данных. Функция get_ml_pipeline возвращает новый экземпляр VideoPipeline для каждого запроса. Функция get_streaming_pipeline возвращает или создает пайплайн для стриминга с сохранением состояния между запросами.

### 4.5 Перечисления

Файл backend/app/core/enums.py содержит перечисления для типов данных: SessionStatus (PENDING, PROCESSING, COMPLETED, FAILED), SourceType (FILE, VIDEO, STREAM), FatigueLevel (ALERT, MILD_FATIGUE, SEVERE_FATIGUE), EventType (EYE_CLOSURE, YAWN, HEAD_DOWN, FACE_ABSENT), SeverityLevel (LOW, MEDIUM, HIGH).

## 5. Конфигурация и параметры

### 5.1 Параметры видеообработки

Система использует параметры для оптимизации производительности и точности. FRAME_PROCESSING_INTERVAL определяет, каждый N-й кадр обрабатывается (по умолчанию 5). Это значительно снижает нагрузку на CPU при обработке видео с высокой частотой кадров.

PERCLOS_WINDOW_SEC определяет размер скользящего окна для вычисления PERCLOS (по умолчанию 60 секунд). Все данные хранятся в памяти за этот период.

### 5.2 Пороги детекции

Пороги настраиваются в зависимости от условий эксплуатации. EAR_THRESHOLD = 0.20 является стандартным значением для определения закрытых глаз, но может варьироваться в зависимости от освещения и индивидуальных особенностей. MAR_THRESHOLD = 0.50 используется для определения открытого рта. HEAD_PITCH_THRESHOLD_DEG = 20.0 градусов определяет значительный наклон головы вниз.

### 5.3 Уровни PERCLOS

Система использует два порога PERCLOS для классификации уровня усталости. PERCLOS_MILD = 0.35 (35%) указывает на легкую усталость. PERCLOS_SEVERE = 0.70 (70%) указывает на тяжелую усталость.

Исследования показывают, что PERCLOS выше 0.40 коррелирует с высоким риском засыпания за рулем.

## 6. База данных

### 6.1 Модели данных

Модели базы данных определены в backend/app/models/db_models.py. Основные модели включают AnalysisSession для сессий анализа, FatigueEventDB для событий усталости, FrameResultDB для результатов обработки кадров.

### 6.2 Схемы Pydantic

Схемы для валидации и сериализации определены в backend/app/schemas/. Основные схемы включают FrameAnalysisResponse для ответа анализа кадра, FatigueScoreSchema для оценки усталости, FatigueEventSchema для событий, AnalysisSessionStatus для статуса сессии, EventFilter для фильтрации событий.

### 6.3 Сервис анализа

AnalysisService backend/app/services/analysis_service.py предоставляет методы для работы с сессиями и событиями. Функция create_session создает новую сессию анализа. Функция update_session обновляет статус и прогресс сессии. Функция save_events сохраняет события в.batchном режиме. Функция save_frame_results сохраняет результаты обработки кадров. Функция get_session получает сессию по ID. Функция list_sessions получает список сессий с пагинацией. Функция get_session_events получает события с фильтрацией.

## 7. API эндпоинты

### 7.1 Системное здоровье (health)

GET /health — эндпоинт для проверки здоровья системы. Проверяет загрузку ML модели и подключение к базе данных. Возвращает статус, флаги model_loaded и db_connected.

### 7.2 Анализ кадра (analysis)

POST /api/v1/analysis/frame — анализ одиночного кадра. Принимает загруженный файл изображения (JPEG или PNG), опциональный session_id, опциональный timestamp. Возвращает FrameAnalysisResponse с результатами анализа, оценкой усталости и landmarks.

POST /api/v1/analysis/upload — асинхронная загрузка видео для анализа. Принимает видеофайл (MP4, AVI, MOV и др.), создает сессию анализа, запускает обработку в фоновом режиме. Возвращает AnalysisSessionStatus с ID сессии и начальным статусом.

GET /api/v1/analysis/{session_id}/status — получение статуса сессии анализа. Возвращает текущий статус, прогресс, длительность, количество обработанных кадров.

### 7.3 События (events)

GET /api/v1/events/session/{session_id} — получение событий усталости для сессии. Поддерживает фильтрацию по event_type, severity, start_time, end_time, limit, offset. Возвращает EventsResponse со списком событий и общим количеством.

## Глоссарий

**EAR (Eye Aspect Ratio)** — отношение сторон глаза, метрика для определения состояния глаз.

**MAR (Mouth Aspect Ratio)** — отношение сторон рта, метрика для определения зевания.

**PERCLOS** — процент времени закрытых глаз в скользящем окне, основной индикатор усталости.

**MediaPipe Face Mesh** — модель машинного обучения Google для извлечения 468 ключевых точек лица.

**FeatureWindow** — структура данных для хранения исторических признаков в скользящем окне.

**FatigueScore** — итоговая оценка состояния усталости водителя.
